# Session 2026-10-21

[Session 2026-10-20](session_20261020.md) resulted in the call stack for Mantastic Voyage and it was discovered that a hash (`0x1bd48906e119a954`) is used to unlock it.
During this session, we investigate how a trophy hash maps to a trophy ID with the goal to find the Gone Viral trophy hash. With the hash known, we can search through the binary and find which conditions trigger the Gone Viral trophy.

## Hash to Trophy ID Mapping

Three breakpoints were set inside `FUN_004b11d4` ([Central Trophy Request Function](session_20261020.md#central-trophy-request-function)) while triggering Mantastic Voyage.

| BP | Address | Register | Value | Confirms |
|---|---|---|---|---|
| A | `0x004b12c4` | `r3` | `0x1bd48906e119a954` | Hash enters `FUN_004b10a0` intact |
| B | `0x004b12c8` | `r3` | `0xC` | `FUN_004b10a0` resolves hash → trophyId `0xC` |
| C | `0x004b12d0` | `r3`/`r4` | `0xC` / `0x0` | Resolved trophy ID forwarded to `FUN_004a2e70` |

Key finding: the hash to trophy ID mapping is not a static table in the ELF. It is a runtime component/property registry. `FUN_004b10a0` uses:

- `FUN_0073f238(0x9cb9012080f727b9, hash)` — looks up the `TrophyDefinition` object by
  hash in the global component registry
- `FUN_0073a040(obj, 0xce07c47e53576879)` — reads the enabled flag property
- `FUN_0073a040(obj, 0x4042d2f96c4e4b8c)` — reads the trophy ID integer property

The three 64-bit constants are property key hashes (component type, enabled flag, trophyId). The integer `0xC` lives in a runtime data object populated from game data at boot.

### Trophy ID Property Key Hash

The `0x4042d2f96c4e4b8c` constant mentioned above was not discovered at runtime, but it was read directly from the Ghidra decompilation of `FUN_004b10a0`. Decompiling that function produced:

```c
undefined4 FUN_004b10a0(undefined8 param_1)
{
  ...
  uVar1 = FUN_0073f238(0x9cb9012080f727b9, param_1);  // find TrophyDefinition by hash
  FUN_0073a568(local_30, uVar1, 0);
  if (local_30[0] != 0) {
    pcVar2 = (char *)FUN_0073a040(local_30, 0xce07c47e53576879, 0); // read "enabled" flag
    ...
    if (*pcVar2 != '\0') {
      puVar3 = (undefined4 *)FUN_0073a040(local_30, 0x4042d2f96c4e4b8c, 0); // read "trophyId"
      ...
      uVar4 = *puVar3;   // dereference → the integer trophyId
    }
  }
  return uVar4;
}
```

Ghidra embedded the constant `0x4042d2f96c4e4b8c` as a literal in the decompiled output because the PPC disassembly builds it from immediate instructions (`lis`, `ori`, `rldicr`, `oris`, `ori`) — the same pattern used to build the trophy hash constants in `FUN_00500734`. Ghidra reassembles these into a single 64-bit immediate in the decompiler output.

This constant is the property key hash for the `trophyId` field inside every `TrophyDefinition` object in the component registry. It is the hashed form of whatever string the game engine uses internally to name that field.

## `TrophyDefinition` Object Layout

Using breakpoint `0x004b1190` (inside `FUN_004b10a0`, at the trophy ID property read call) during Mantastic Voyage trigger:

- `r3` = `0xd0068720` → `*(r3)` = `0x30978ec0` = `OBJ_A` (Mantastic Voyage node)
- After `FUN_0073a040` returns: `r3` = `0x30903008` → `*(r3)` = `0x0000000C` (trophyId)

Searching memory for the Mantastic Voyage hash `1b d4 89 06 e1 19 a9 54` in `0x309xxxxx`:
- `0x309282e0` — bucket array slot
- `0x30978ed8` — inside node at `OBJ_A + 0x18`

Node layout confirmed by comparing a second trophy (`0xb598d5bd5d16ec4f`, score > 9,999):

```
node + 0x00  : uint32  pointer to property data block
node + 0x04  : uint32  0x00000001  (ref count)
node + 0x08  : uint32  0x00020002  (schema descriptor)
node + 0x0c  : uint32  0x00000000  (padding)
node + 0x10  : uint64  0x0000000000000000
node + 0x18  : uint64  trophy hash  ← 64-bit hash key
```

Property data block layout (confirmed across multiple trophies):
```
block + 0x00  : uint64  0x4042d2f96c4e4b8c  (property key hash for "trophyId")
block + 0x08  : uint32  trophyId integer
block + 0x0c  : ...
```

## Find Gone Viral `TrophyDefinition` in Memory

Instead of walking property blocks by stride, search directly for the 12-byte sequence (property key hash `0x4042d2f96c4e4b8c` followed immediately by the trophy ID `0x13`) in the RPCS3 memory viewer:

```
40 42 d2 f9  6c 4e 4b 8c  00 00 00 13
```

This resulted in exactly one hit at `0x30903220`, the Gone Viral property block. Search for the 4-byte pointer `0x30903220` to find the owning node. The Gone Viral `TrophyDefinition` node is located at `0x309791f0`.

Node at `0x309791f0`:
```
+0x00: 30903220          → property block (trophyId = 0x13)
+0x04: 00000001
+0x08: 00020002
+0x0c: 00000000
+0x10: 00000000
+0x14: 00000000
+0x18: 17e8ac10 14ab97a5 → Gone Viral trophy hash
```
