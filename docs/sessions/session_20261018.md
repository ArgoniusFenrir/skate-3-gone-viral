# Session 2026-10-18

Due to the overhead of restarting RPCS3 in debug mode to reverse engineer the static analysis findings from previous sessions, RPCS3 patches were created to speedup debug significantly and no longer require a restart of the game.

## Problem: Existing Debug Loop with Huge Overhead

Before this session, debugging inside RPCS3 required:

1. Boot the game
2. Set a breakpoint in the RPCS3 debugger
3. Trigger Mantastic Voyage (3+ manuals in a line)
4. Observe the breakpoint
5. Restart the game entirely before repeating, because the trophy was now marked as unlocked and the game would not attempt to unlock it again

The restart cost was significant.
The goal for this session was to eliminate it by patching
the game's binary in memory via RPCS3's `imported_patch.yml` facility, which lets you replace arbitrary instructions in the emulated address space at boot without modifying the
ELF on disk.

## Patch 1 — Stub `sceNpTrophyUnlockTrophy`

### Motivation

The first patch was to stop the trophy from actually being committed to the RPCS3 profile.
This keeps the trophy in its locked state across sessions, so the same trophy trigger can be exercised repeatedly without resetting the profile.

### Patch

A [NOP patch](../../rpcs3/imported_patch.yml#3-13) was applied to `sceNpTrophyUnlockTrophy`, replacing the `bl` instruction with `nop` so the SDK call never fires.

### Result

Confirmed via live debugger: the trophy no longer popped in-game and did not appear in the RPCS3 trophy list after triggering Mantastic Voyage. The patch worked as intended.

## Patch 2 — Disable Local Bitset Update

### Motivation

After Patch 1, triggering Mantastic Voyage a second time in the same session produced no activity.
The trophy worker thread was never woken up and no breakpoint on
`_opd_FUN_004acbc8` or `TrophyWorkerThread` was hit on the second attempt.

Prior debug notes mentioned that after `sceNpTrophyUnlockTrophy` is called, a local bitset vector is updated to record the trophy as unlocked.

This bitset is checked before enqueueing a trophy request — it acts as an early-exit gate in `FUN_004b11d4` / `FUN_004b12ec` to avoid re-queuing a trophy that has already been awarded.
Because the Patch 1 prevented `sceNpTrophyUnlockTrophy` from running but did not prevent the bitset update, the game still recorded Mantastic Voyage as unlocked in the bitset after the first trigger, and silently dropped every subsequent trigger.

### Patch

A [patch](../../rpcs3/imported_patch.yml#13-22) was applied to the `TrophyWorkerThread`, changing the `bgt` instruction to `b 0x004bdfdc` to skip 3 bitset update instructions.


### Result

With both patches applied:

- Triggering Mantastic Voyage a second time (and subsequent times) in the same session worked as expected.
- The trophy worker thread was woken each time.
- Breakpoints on the worker thread path fired on every trigger, not just the first.
- The trophy never popped in the RPCS3 profile.

This gave a clean, repeatable debug loop without restarting the game.
