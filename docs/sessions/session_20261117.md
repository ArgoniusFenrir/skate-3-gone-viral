# Session 2026-11-17

[Session 2026-10-22](session_20261022.md#result) found the call site and trophy hash for Gone Viral. In this session, we dive into the netcode of Skate 3.

## Setup

The game ran in RPCS3 with an RPCN account connected to the public custom server [Skate3BlazeServer](https://github.com/skate6743/Skate3BlazeServer). The server's `README.md` mentions it requires a modified `EBOOT.BIN`. After decompiling and comparing against the `1.05` `EBOOT.BIN`, an [RPCS3 patch](../../rpcs3/imported_patch.yml#34-43) was written and enabled instead.

### Gone Viral Unlock Test

In the run from row 6 above, `r0` was set to `1` at `0x00467e80` with the RPCS3 register editor. Results:

1. `0x0046ec28` hit. The event was `0x30680a20` with vptr `0x017acc90` (class A). Slot `+0x18` returned `0x2b`. `LR = 0x0046ebe0`.
2. `0x0046ed0c` hit with `r3 = 0x17e8ac1014ab97a5` (the Gone Viral hash) and `r4 = 0`.
3. The Gone Viral trophy unlocked.

A class A event with `event+0x130 != 0` reaches `skate3_unlock_gone_viral` and unlocks the trophy. The flag was the only thing blocking the unlock in that run.

## Observations Through Static Analysis

### Handler `skate3_unlock_gone_viral` (`0x0046eb04`)

- It has no `bl` callers. Its descriptor `0x017fc518` is referenced only from slot `+0x38` of the vtable `0x017ac5f8`. Thunks `0x01177c74` (`this - 0x40`) and `0x01177c7c` (`this - 0x34`) reach it from other base-class views. It can only be reached through a virtual call.
- It calls slot `+0x18` on the event and continues only if the result is `0x2b`.
- It reads the byte at `event+0x130` (`lbz` at `0x0046ec28`). If nonzero, it calls `FUN_004b11d4` (`skate3_themain_thread_trigger_trophy_hash`) with `0x17e8ac1014ab97a5, 0` (call at `0x0046ed0c`).
- A loop over `this+0xb40..0xb44` runs after the trophy call, so it does not gate the trophy.

### Class A Event (vptr `0x017acc90`)

- Slot `+0x18` is `li r3,0x2b` (code `0x01167858`).
- Slot `+0x48` is `_opd_FUN_0116f2ec(event, holder)`. If slot `+8` of `*holder` returns `0x12bdaa8e`, it copies the byte at `object+8` into `event+0x130`. The registry decompiled at `0x000bc970` ties `0x12bdaa8e` to `BoolContainer`.
- No caller of `_opd_FUN_0116f2ec` was found.
- Two other vtables return `0x2b` from slot `+0x18`: `0x017aafc0` (code `0x01167c70`) and `0x017cc0b8` (code `0x013b3628`). Nothing that builds them is known.

### Builder `FUN_00467a38`

- It allocates a `0x134`-byte event (`li r3,0x134` at `0x00467e30`) with the vptr from TOC slot `0x183c46c` (`0x017acc90`) and posts it through `FUN_004a1abc` (`bl` at `0x00468094`). It also sets the properties `"Infect"` and `"userIds"` from the id list at `this+0xb40`.
- The only store to `event+0x130` is `stb r0,0x130(r21)` at `0x00467e80`, after `li r0,0` at `0x00467e74`. The builder always writes `0`.
- Gates before the allocation:

| Gate | Address | Exits without an event when |
|---|---|---|
| 1 | `0x00467d84` | `FUN_004ad4ec()` returns `0`. |
| 2 | `0x00467d98` | The roster vector is empty. |
| 3 | `0x00467db0..0x00467df0` | Every roster id is already in the cache at `this+0xb40`. |

- The roster loop at `0x00467c7c` reads six 8-byte ids at `*(this+0x170)+0x10+8*i`.
- The builder also holds an unrelated trophy trigger for hash `0x6dd8d776a59cba15`.
- Callers: `FUN_00467a38` ← `FUN_00480838` (`bl` at `0x00480888`). `FUN_00480838` ← `bl` at `0x00481b58` (inside `FUN_00481610`, branch for phase `0`) and `bl` at `0x004822d8` (inside code at `0x00482224`, which has no Ghidra function).

### Event Delivery

- `_opd_FUN_004d14f0` (event post) calls `_opd_FUN_004a353c` and `_opd_FUN_004a35d0`. Both broadcast loops walk a vector at `this+0xc..0x10` and call slot `+8` on each entry. `_opd_FUN_004d14f0` has no direct callers.
- `_opd_FUN_004b69d8(this, holder, listener)` is a targeted dispatcher (descriptor `0x017feec8` at `0x017ad970`). It has no direct callers.
- Switch methods: `_opd_FUN_0046f1ac` switches on the event type (`0x0e`..`0x3d`, table at `0x0046f214`). `_opd_FUN_0046a9b4` switches on the result of slot `+8` (`0x00`..`0x36`, table at `0x0046aa48`). Type `0x2b` is not handled by `_opd_FUN_0046f1ac`, and type `0x36` goes to its default return. Ghidra cannot recover these inline jump tables.

### Blaze Receive Path

`FUN_00873080(userObj, component, command, body, size)` selects a handler object by component and calls its slot `+8`.

| Component | Offset in `param_1` | Component | Offset in `param_1` |
|-----------|---------------------|-----------|---------------------|
| `1` | `+0x14` | `0xe` | `+0x40` |
| `3` | `+0x24` | `0xf` | `+0x44` |
| `4` | `+0x2c` | `0x14` | `+0x3c` |
| `5` | `+0x4c` | `0x15` | `+0x54` |
| `6` | `+0x48` | `0x16` | `+0x50` |
| `7` | `+0x58` | `0x17` | `+0x5c` |
| `9` | `+0x60` | `0x18` | `+0x20` |
| `0xa` | `+0x18` | `0x19` | `+0x10` |
| `0xb` | `+0x1c` | `0x1b` | `+0x34` |
| `0xc` | `+0x30` | `0x20` | `+0xc` |
| `0xd` | `+0x38` | `0x7802` | `+0x28` |

Receive chain: `recv` (`FUN_008dcd7c`) → `FUN_008dcf18` → `FUN_008ed988` → `FUN_008bd41c` → `FUN_008bddf4` (frame reader) → `_opd_FUN_008be2f4` → `_opd_FUN_008bf454` (router; message type `2` → `FUN_00873080`).

Packet header as read by the parser (bytes from the start of the header): `+0` u16 body size, `+2` u16 component, `+4` u16 command, `+8` high nibble message type and low nibble user index, `+10` u16 low bits of the message number. Flag bit `0x10` in byte `+9` adds 2 header bytes and bit `0x20` adds 4.

`_opd_FUN_008ac6ec` is a jump-table decoder on `command - 10`. Its entry for command `0xa` is at `0x008acb34` (decoded by hand). It calls a decoder at `0x00898c60`, then a listener through slot `0` of the object at `this+0xc`.

## Results

Forcing the flag byte at `event+0x130` to `1` in an infect event built by the game unlocked the trophy. The handler side of the unlock works. What makes the flag `1` in a real infection was not found.
