# Session 2026-11-21

[Session 2026-11-17](session_20261117.md) showed that a class A event with `event+0x130 != 0` unlocks Gone Viral, but not who sets that flag. In this session, we find out what the class A event is and what the game sends over the network when it builds one.

## Setup

The game ran in RPCS3 with an RPCN account connected to the public custom server [Skate3BlazeServer](https://github.com/skate6743/Skate3BlazeServer). Breakpoints were set in `themain_thread` at `0x00467dac` (cache check in `FUN_00467a38`) and `0x00467e80` (store to `event+0x130`), later also in the HTTP client path. A packet capture was taken on the host using:

```console
$ tcpdump -i any -A -s0 'tcp port 80'
```

## Observations at Runtime

### Builder and Cache

| # | Setup | Observation |
|---|---|---|
| 1 | First game boot, first join | `this = 0x4208dfa0`. The cache at `this+0xb40` was empty. The roster held one id, `0x1a6e`. `0x00467e80` hit, so the builder built an event. Copying registers at the breakpoint timed the connection out, so the lobby was never joined. |
| 2 | Same session, joined another lobby | The cache held one id, `0x1a6e`, equal to the roster. `0x00467e80` did not hit. |
| 3 | Test 2 setup, with `r8 = r30` set at `0x00467dac` to force a rebuild | `0x00467e80` hit. `0x0046ec28` hit with a class A event (`0x3048aaa0`). Slot `+0x18` returned `0x2b`. |
| 4 | Repeat of test 3 | The byte at `event+0x130` was `0x00`. |
| 5 | Breakpoint on the flag setter `_opd_FUN_0116f2ec` in all of the above | Never hit. |

Results:

- With an empty cache the builder builds an event. With the cache equal to the roster it does not. The cached players are not set on the first join. Afterwards the cache holds the same ids as the roster (see row 6 of [session 2026-11-17](session_20261117.md)).
- A locally built infect event has `event+0x130 == 0`, and the setter is not called between build and handler.

### The Event is Sent as an HTTP Request

Breakpoint runs with the rebuild forced at `0x00467dac`:

| # | Breakpoint | Observation |
|---|---|---|
| 6 | `0x00468094` (`bl FUN_004a1abc` in the builder) | The event is at `0x3048c760`. Its bytes are `01 7a cc 90  00 00 00 01  30 59 8c 90  30 59 8c 94`: vptr `0x017acc90`, `+8 = 0x30598c90`. |
| 7 | `0x004a1b34` (`bctrl` in `FUN_004a1abc`) | `CTR = 0x0119ca04`. |
| 8 | `0x004b2dd8` | `r3 = 0x300603e0`. `*r4 = 0x3048c760`, the same event as in row 6. The word at `r3+0x48` is `0x300325a0`, non-zero, so the function does not return `-1`. |
| 9 | `0x00828c88` (`bl send`), thread `http_worker` | Three hits with `r4 = 0x30598c90` (the text `POST`, `r5 = 4`), which equals `event+8` from row 6. Later hits: another `POST` object (`0x30652e60`), then single tokens (a space, `HTTP/1.1`, `http://`, `\r\n`, `:`, `*`). The client writes a request in small pieces, one `send` per piece. |

RPCS3 packet capture:

| Direction | Content |
|---|---|
| Out, 4 bytes | `POST` |
| Out | `/skate3/ws/SkateProfile.asmx/Infect HTTP/1.1` |
| In, 25 bytes | `HTTP/1.1 100 Continue` |
| Out, 25 bytes | Body `platformId=2&userIds=6766` |
| In, 341 bytes | `HTTP/1.1 404 Not Found` |

- The method is `POST`. The body is form-encoded: `platformId=2&userIds=<ids>`. `6766` is `0x1a6e`, the local id from the cache and roster. Only one id was seen, so the separator for several ids was not observed.
- The server host in the capture is the public IP address of the [Skate3BlazeServer](https://github.com/skate6743/Skate3BlazeServer), port 80. It replied `404` to the `Infect` request.

## Observations Through Static Analysis

### The class A event is a web-service request named `Infect`

- The builder `FUN_00467a38` allocates `0x134` bytes and calls `FUN_004bd1dc(event, 2, "Infect")` (`li r4,2` at `0x00467e60`, `bl` at `0x00467e64`). This leads through `FUN_004b404c` to `FUN_004b3d38(2, "Infect", ...)`, a URL builder.
- `FUN_004b3d38` indexes an inline jump table at `0x004b3da4`. Ghidra cannot recover it, so it was decoded by hand from the ELF bytes. Each index loads one format string:

| Index | Format string |
|---|---|
| `1` | `/skate3/ws/SkateReel.asmx/%s` |
| `2` | `/skate3/ws/SkateProfile.asmx/%s` |
| `3` | `/skate3/ws/SkateDLC.asmx/%s` |
| `4` | `/skate3/ws/SkateCAS.asmx/%s` |
| `5` | `/skate3/ws/SkateMsg.asmx/%s` |
| `6` | `/skate3/ws/SkateTeam.asmx/%s` |
| `7` | `/skate3/ws/SkateFeed.asmx/%s` |
| `8` | `/skate3/ws/SkateStats.asmx/%s` |

  Index `2` gives `/skate3/ws/SkateProfile.asmx/Infect`.
- The builder joins the cache ids with `,` into the `userIds` value.
- The method id `4` (`addi r6,r0,4` at `0x004bd220`) is stored by `FUN_00817b5c` at `event+0x1c`, and the method string at `event+8`. `FUN_0080e6cc` maps id `4` to `POST` through an inline jump table at `0x0080e6f0`.

### From the post to the HTTP client

- `FUN_004a1abc` calls slot `+0x18` on `**p1`, then slot `+8` on the result. The observed target `0x0119ca04` is `subi r3,r3,8; b 0x004b2dd8`. It is slot `+8` of the secondary vtable `0x017ad988`, at offset `+8` of an object with vptr `0x017ad918`.
- `_opd_FUN_004b2dd8` returns `-1` if `this+0x48 == 0`. Otherwise it adds two headers (`BLAZE-SESSION`, `BLAZE-PLATFORM`) and queues the request through `FUN_00f2f0f0` → `FUN_00b52514` → `FUN_00b52328`.
- The game imports no `cellHttp` request functions, only `cellHttpInit`, `cellHttpsInit`, `cellHttpEnd`, `cellHttpsEnd` and the cookie init/end calls. It builds HTTP requests itself over `send` and `connect`.

### How the flag is set

Class A vtable (`0x017acc90`):

| Slot | Code | Role |
|---|---|---|
| `+0x40` | `_opd_FUN_004b7b58` | Returns early if the string `IgnoreIncomming` matches. Otherwise builds an `XmlSerializerImpl` deserializer and calls slot `+0x44` with the resulting container. |
| `+0x44` | `_opd_FUN_004b7638` | For type id `0x2ff145ec` (`ErrorContainer`) it stores a field. Otherwise it calls slot `+0x48`. |
| `+0x48` | `_opd_FUN_0116f2ec` | The flag setter. If the container's type id is `0x12bdaa8e` (`BoolContainer`), it copies the byte at `container+8` into `event+0x130`. |

- The container writer `_opd_FUN_000c0f18` serialises a `BoolContainer` as one element with one child named `value`. The type-id dispatcher `_opd_FUN_000d1a2c` maps `0x12bdaa8e` to `BoolContainer`.
- No direct call to slot `+0x40` on a class A event was found. The call is virtual (662 candidate sites).

### String `hasFlu`

The string `hasFlu` (`0x0149a2e8`, pointer at `0x0182dee0`) is a field of the `ProfileInfo` container, written last by `_opd_FUN_000d07d8`. Other readers are `FUN_004e976c` and `_opd_FUN_012f6c30`. Nothing found links it to the `Infect` request or the trophy.

### Custom Server

This section contains observations from static analysis of the [Skate3BlazeServer](https://github.com/skate6743/Skate3BlazeServer).

- `Servers/HTTP/HttpServer.cs` routes `/skate3/ws/SkateReel.asmx` and `/skate3/ws/SkateProfile.asmx` through one `switch (action)`. There is no `Infect` case, and the `default` branch sets status `404`.
- `SkateDLC`, `SkateCAS`, `SkateMsg`, `SkateTeam`, `SkateFeed` and `SkateStats` are not routed.
- Existing responses use the shape `<IntegerContainer><value>0</value></IntegerContainer>` and `<LongContainer><value>...</value></LongContainer>`.
- `ServerLogger` logs only sign-ins and errors, so rejected HTTP requests left no trace.
- The server reads `BLAZE-SESSION` in `HttpUtils.GetAuthenticatedUser`.

## Results

The class A event is a web-service request: when the builder posts it, the game sends `POST /skate3/ws/SkateProfile.asmx/Infect` with the body `platformId=2&userIds=<ids>`. The public [Skate3BlazeServer](https://github.com/skate6743/Skate3BlazeServer) answered `404`, because it doesn't support the `Infect` case. The static chain says that a `BoolContainer` reply reaches the flag setter at `event+0x130`, which the handler `skate3_unlock_gone_viral` needs. The next step is to answer the request with a `BoolContainer` and see whether the trophy unlocks.
